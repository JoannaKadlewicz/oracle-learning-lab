# Plans (guest / user / pro / admin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace per-workspace free/subscribed access with account plans (guest, user, pro, admin), add guest access with progress carried into a new account, per-account limits, and logo + coming-soon tiles in the picker.

**Architecture:** The plan is `User.role`. `access/plans.py` holds plan limits (defaults per plan in app settings, per-account overrides) and replaces `FreeLimits`; `access/policy.py` decides membership and what a plan may do; `UserContexts` keeps resolving one `Access` per request, now carrying the plan and its limits. Guests are real accounts (identity provider `guest`) so every existing code path works for them; registering from a guest session adopts the guest's data.

**Tech Stack:** Python 3.14 stdlib web app, pytest, ruff; vanilla ES modules, strict CSP; SQLite/Oracle stores; i18n catalogs (server and front `pl.json`).

**Spec:** `docs/superpowers/specs/2026-10-22-plans-design.md` (builds on `docs/superpowers/specs/2026-10-22-workspaces-design.md`).

## Global Constraints

- Tests `.venv/bin/python -m pytest -q -p no:cacheprovider`; lint `.venv/bin/python -m ruff check src tests`; clean after every task.
- Roles exactly `guest`, `user`, `pro`, `admin`. Access rows mean membership; new rows are written with level `"member"`.
- Defaults: guest 20 questions/day, 20 cards/day, 2 free topics, 0 exercises; user 10 exercises/day, everything else unlimited; pro unlimited. Settings keys `plan_guest_questions`, `plan_guest_cards`, `plan_guest_topics`, `plan_user_exercises`; per-account override key `limits:<user_id>` (JSON `{questions, cards, exercises, topics}`, missing = plan default).
- Limit answer: 403 `{"error", "limit": "questions"|"cards"|"exercises"}`; plan refusal: 403 `{"error": "This needs the Pro plan."}` for pro-only features, `{"error": "Create a free account to use this."}` for guest-blocked ones.
- Every user-visible string in both catalogs (gender-neutral Polish). Never touch 8080; 8071 only for the final redeploy; never `pkill -f`; never print secrets. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `feature/plans` from `feature/workspaces`.

## Review Focus

1. A pre-migration `user` with a `subscribed` row must become `pro` and keep SQL lab in every workspace it had — Task 1 test.
2. A guest must never cause a practice schema or SQL run, through any endpoint (grade, run, visualize, schema, reset-data, flashcard try-it, provisioning hook) — Task 3 test.
3. Registering from a guest session keeps attempts, cards, notes and the workspace; registering without one is unchanged — Task 2 test.
4. The user's 11th graded exercise of the day is refused even after a progress reset — Task 3 test.
5. A per-account override beats the plan default (in both directions: more and fewer) — Task 1 test.

**Interfaces (produced):**
- `plans.Limits(questions: int | None, cards: int | None, exercises: int | None, topics: int | None)` — `None` = unlimited; `public() -> dict`.
- `plans.limits_for(role: str, user_id: str, settings) -> Limits` — plan default overlaid with the account override.
- `plans.PlanDefaults.load(settings)` / `.save(settings)` / `.parse(dict)` for the four plan keys; `plans.set_override(settings, user_id, dict | None)`, `plans.override(settings, user_id) -> dict`.
- `plans.can(role, feature) -> bool` for features `"sql_lab"`, `"mock"`, `"exercises"`, `"many_workspaces"`.
- `policy.level_in(role, rows, ws) -> "none" | "member"` (admin: member everywhere); `policy.usable`, `policy.current_workspace` unchanged in shape.
- `migration.migrate_plans(stores, clock, audit) -> int` (after `migrate_roles`).
- `Access` gains `plan: str` and `limits: Limits` (replaces `FreeLimits`); `public()` → `{workspace, plan, usable, limits, used}` with `used` including `exercises`.
